# 画面・機能仕様

## 1. ルーティング

| URL | ページ | 実装 | データ取得 |
| --- | --- | --- | --- |
| `/` | トップ | `src/App.tsx` | 作品最大5件 |
| `/works` | 作品一覧 | `src/pages/Works/index.tsx` | 作品最大100件 |
| `/works/:id` | 作品詳細 | `src/pages/WorkDetail/index.tsx` | 指定 ID の作品1件 |

ルーティングは `src/main.tsx` で定義します。作品詳細への直接アクセスに対応するため、Vercel では `/works/:id` を `/index.html` に rewrite します。

## 2. トップ画面

トップ画面は次の順に表示します。

### 2.1 Header

- サイトアイコンを表示する。
- About、Skills、Works、Contact の各セクションへページ内移動する。
- ハンバーガーメニューの開閉状態をコンポーネント内で管理する。
- ナビゲーション選択後はメニューを閉じる。

### 2.2 Hero

- 背景に `DarkVeil` のアニメーションを表示する。
- 名前とウェルカムメッセージを文字単位のアニメーションで表示する。

### 2.3 About Me

- `src/data/profile.ts` の `profile` をラベル・値形式で表示する。
- 改行を含む所属・自己紹介を表示する。

### 2.4 Career

- `src/data/profile.ts` の `career` を時系列で表示する。
- リンクがある経歴は新しいタブで作品詳細等を開く。
- 画面幅が 768px を超える場合は、スクロールに連動した横方向のアニメーションを使う。

### 2.5 Skills

- `src/data/skills.ts` のスキル名、レベル、カテゴリ、SVG アイコンを表示する。
- カテゴリは `frontend`、`backend`、`devops`、`design`、`other` のいずれかを複数指定できる。
- レベルは現行データで 1〜4 の数値を使用する。

### 2.6 Works

- `GET /api/works?limit=5&offset=0&orders=publishedAt` を呼び出す。
- 作品を Splide のループスライダーとして表示する。
- 各作品にタイトル、概要、使用技術、サムネイルを表示する。
- 作品選択時は `/works/:id` へ移動する。
- `View all works` から `/works` へ移動する。
- 取得失敗時はコンソールへエラーを出力し、画面内のエラー表示は行わない。

### 2.7 Contact

- 入力項目は名前（必須）、所属（任意）、メールアドレス（必須）、メッセージ（必須）。
- ブラウザ標準の `required` と `type="email"` による入力検証を利用する。
- 送信中はボタンを無効化し、ラベルを「送信中...」に変更する。
- 成功時は全項目を空にして成功メッセージを表示する。
- 失敗時は「送信に失敗しました」を表示する。

### 2.8 Footer / Analytics

- フッターを表示する。
- Vercel Analytics によるアクセス解析をトップ画面で有効にする。

## 3. 作品一覧画面

- 最大100件の作品を取得する。
- カードをグリッド表示する。
- カードにはタイトル、概要、使用技術、サムネイルを表示する。
- カード選択時は `/works/:id` へ移動する。
- 現行実装にはローディング表示、空データ表示、取得失敗時の画面表示、ページネーションはない。

## 4. 作品詳細画面

### 状態

| 状態 | 表示 |
| --- | --- |
| 読み込み中 | `Loading...` |
| 取得失敗 | API ステータスを含むエラーメッセージ |
| ID 不正 | `Invalid work id` |
| データなし | `No work data found.` |
| 取得成功 | タイトル、概要、画像、詳細表 |

### 詳細表

値が存在する項目のみ表示します。ただし使用技術の行は常に表示対象です。

| 表示名 | フィールド | 表示方法 |
| --- | --- | --- |
| 使用技術 | `tech` | 技術名を並べる |
| 受賞 | `awards` | 複数行 |
| 背景 | `background` | テキスト |
| 目的 | `purpose` | テキスト |
| 機能 | `function` | 複数行 |
| 制作人数 | `number` | `N人` |
| 担当 | `role` | 複数項目 |
| 発表 | `presentation` | 複数行 |
| 制作期間 | `duration` | テキスト |
| Webサイト | `webUrl` | リンク |
| GitHub | `github` | リンク |
| 外部記事 | `outname`, `outLink` | 名前付きリンク |
| 制作日 | `date` | テキスト |
| 詳細説明 | `description` | リッチテキストを Markdown に変換して描画 |

詳細説明は `rich-editor-to-markdown-parser` で変換し、`react-markdown` と `remark-gfm` でテーブル等を含む Markdown としてレンダリングします。

## 5. レスポンシブ・アクセシビリティ上の仕様

- `viewport` メタタグを設定する。
- ヘッダーのメニューボタンには日本語の `aria-label` を設定する。
- 画像には作品名またはアイコンを表す `alt` を設定する。
- 経歴の横スクロール演出は 768px 以下で停止する。
- Splide の左右余白は 768px 以下で縮小する。

現行実装では、問い合わせ結果のライブリージョン、詳細画面からの戻る導線、全ページ共通ヘッダー、フォーカス制御は明示的に実装されていません。
